# 보급소 Unity 연결 계약

보급소 컨트롤러에는 게임 전용 클래스 의존성이 없습니다. uGUI와 TextMeshPro를 사용하는 프리팹에서 `catalog`와 `view`를 연결하고, `ISupplyDepotAccount`를 구현한 게임 컴포넌트를 `accountProvider`에 할당하거나 `BindAccount(account)`를 호출합니다. 데모의 `DemoSupplyDepotAccount`는 별도 메모리 계정으로, 기본 잔액과 시작 아이템 수량을 인스펙터에서 바꿀 수 있습니다. 패널을 닫고 다시 열어도 같은 계정 상태를 읽으며, 저장 파일이나 PlayerPrefs에는 쓰지 않습니다.

## 구매와 런 상태

- 카탈로그에서 ID가 유일한 항목 중 하나를 같은 확률로 고릅니다. 제공 카탈로그에는 81개 항목이 있습니다. 가격과 애니메이션 길이는 카탈로그에서 설정합니다.
- 게임 계정의 `TryPurchase(itemId, cost, out receipt)`가 잔액 및 현재 런의 사용 여부를 검사한 뒤 차감·지급·런 영수증 기록을 한 번에 커밋해야 합니다. 거절한 경우 세 상태를 모두 그대로 두고 `false`를 반환합니다.
- 성공 영수증의 `itemId`는 요청한 ID, `transactionId`는 구매의 고유 ID입니다. `CurrentReceipt`는 구매를 완료한 현재 런의 결과를 유지하며 새 런에서만 `null`이 됩니다. 실제 저장이 필요하면 이 상태와 지급 결과는 게임의 저장 계층에서 함께 관리합니다. 계정의 메서드와 `Changed`는 Unity 메인 스레드에서 사용합니다. 성공 상태는 `Changed` 호출 전에 적용되어야 합니다.
- 릴은 영수증에 기록된 아이템에 멈춥니다. 기본 4.2초는 실제 경과 시간으로 흐릅니다. 건너뛰기나 패널 비활성화는 같은 보상을 확정 표시하며 재구매하지 않습니다. `RewardGranted(SupplyDepotReceipt)`는 이 컨트롤러가 결과를 공개할 때 한 번 발생하는 알림입니다. 아이템 지급은 구매 트랜잭션에서 끝나므로 이 이벤트에서 다시 지급하지 않습니다. 패널 재개방 또는 이전 영수증 복원에는 이 이벤트가 발생하지 않습니다.
- 게임의 런 종료 흐름에서 `NotifyRunEnded()`를 호출합니다. 추첨 중이라면 `SkipAnimation()`으로 이미 커밋된 결과를 먼저 확정한 후 호출합니다. 추첨 중에는 닫기와 런 초기화 요청이 처리되지 않습니다. 초기화는 사용 여부 및 현재 영수증만 지우므로 이전 구매를 환불하지 않습니다.

## 열기, 닫기, 입력

게임의 기존 보급소 상호작용에서 `Open()`을 호출합니다. 패널이 열린 동안 F는 추첨, Esc는 닫기에 연결됩니다. 패널이 닫힌 동안 이 컴포넌트는 키 입력을 읽지 않습니다. 게임 입력 시스템에서 키 충돌을 관리하려면 `automaticKeyboardInput`을 끄고, 패널에 전달할 입력으로 `TryDraw()`, `Close()`, `SkipAnimation()`을 호출합니다. 장착한 EventSystem 입력 모듈은 프로젝트의 활성 입력 방식에 맞춥니다.

`IsOpen`과 `IsDrawing`으로 입력 분기 조건을 확인할 수 있습니다. `OpenChanged(bool)`를 구독해 게임의 입력 라우팅을 조정할 수 있습니다. `manageCursor`가 켜져 있으면 열 때 마우스 커서를 표시하고 닫히거나 비활성화될 때 이전 커서 상태를 복원합니다. 게임에서 커서를 통합 관리한다면 이 설정을 끕니다. 컨트롤러는 게임 시간을 변경하지 않습니다.

Unity 메뉴의 **Tools → Boundary Zero → Verify Supply Depot Transactions**에서 데모 구매 트랜잭션을 검증할 수 있습니다. 자금 부족, 수량 한계, 같은 런 중복 호출, 결과 유지, 런 초기화 후 구매를 확인합니다.
