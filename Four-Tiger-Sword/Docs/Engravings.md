# 각인 트리와 아이템 통합

현재 BoundaryInventory의 아이템 59종과 시너지 11종을 사용한다. 별도 아이템 보유 목록이나 오행 분류를 만들지 않는다.

## 설정과 공방

- `Assets/_Project/Resources/EngravingSettings.asset`: 40개 노드의 ID, 직접 선행 노드, 단계, 수치, 지속시간, 상한과 표시 문구. 무료 `origin`을 제외한 39개 비용은 단계별 10/20/40/80, 합계 1,290 강화석이다.
- `Assets/_Project/Prefabs/UI/HubWorkshop.prefab`: 기존 기본 강화 3종과 각인 트리를 함께 표시한다. 허브의 기존 공방 인스턴스에 프리팹 변경이 반영된다.
- `Assets/UI/PentaUpgrade`: 전달받은 패키지에서 선택 임포트한 트리 UI와 전용 리소스. 기존 TMP 리소스를 덮어쓰지 않는다.
- `starterelement`는 내부 ID를 유지하고 **유품의 계통: 시너지 선택**으로 표시한다.

`PlayerUpgradeService.GetNodePurchaseState`로 설명·비용·선행 조건·잔액을 조회하고 `TryUnlockNode`로 구매한다. 잠긴 노드도 선택할 수 있다. 첫 진입은 기본 강화 탭이고 같은 허브 세션에서는 탭·선택·스크롤·배율을 유지한다. 환불과 초기화는 없다.

저장 v2는 기존 강화석과 HP/ATK/DEF 단계에 `unlockedNodeIds`를 추가한다. v1 파일은 기존 값을 유지해 읽고, 다음 성공적인 저장에서 v2로 기록한다. 파일 저장이 성공하기 전에는 해금·차감·변경 이벤트를 확정하지 않는다. 손상된 노드/선행 관계도 백업 복구 대상으로 검사한다.

## 런과 전투

`PlayerEngravingRuntime`은 런 시작 시 설정과 해금 상태를 복사한다. 아이템 획득·매각·시너지 승급으로 이 스냅샷이나 부활 사용 여부를 초기화하지 않는다. 스테이지 이동은 임시 버프·대상 기록·각인 과회복 방어막을 정리하고, 부활 횟수·처치 골드 소수는 같은 런에서 유지한다.

공격력/최대 체력은 `(기본값 × (1 + 공방 + 각인) + 고정 증가량) × (1 + 아이템·폼 비율)`로 계산한다. 직접 공격의 조건부 피해는 아이템 보너스와 같은 가산 단계, 받는 피해는 기존 아이템 배율에 각인 감소 배율을 각각 곱한다. 각인 공격속도는 전체 공격에 적용하며 아이템의 공격 분류별 배율은 유지한다.

확정 적중의 `ItemDamageContext`가 실제 치명타, 원래 공격/추가 피해, 처치 직전 상태를 전달한다. 치명타 누적·연타·회피 반격의 상태 소비는 유효 적중당 한 번이다. 직접 타격/처치 효과는 아이템·시너지 추가 피해에서 재귀 발동하지 않는다. 전리품 골드는 플레이어에게 귀속된 일반 적 처치의 원래 기본 골드에 별도로 적용한다.

회복 증가는 아이템 회복에도 적용된다. 과회복 방어막은 새 증가분만 아이템 방어막 증가율을 적용한 뒤 최대 체력 10%로 제한한다. 부활은 방어막 흡수 뒤 치명 피해를 가로채 사용 여부·30% 체력·2초 무적을 먼저 확정한다. 기존 피격 아이템은 반응하며 사망 이벤트/일반 다운 반응은 발생하지 않는다.

## 보상과 거래

`RunItemChoiceService`는 출격 유품·일반 방 보상·재선택·보관·수령을 관리한다. 후보는 실제 카탈로그에서 ID와 `candidateKey` 모두 중복되지 않도록 추출하고 기존 `PlayerItemRuntime`으로 지급한다.

- 출격: 1등급 13종에서 최대 3개. 계통 선택은 실제 1등급 후보가 있는 치명·철벽·마무리·거물사냥·숙련·수확 6개를 계산한다. 계통 후보가 하나면 바로 지급한다.
- 일반 전투방: 정상 처치로 처음 완료할 때 3개/각인 보유 시 4개 중 하나. 보스·상점·빈 방 제외. 후보가 없으면 10골드 수령 또는 명시적 건너뛰기이며, 건너뛰기는 골드를 주지 않는다.
- 재선택: 일반 보상에서 런당 3회. 후보 하나를 보관할 수 있다. 실제 교체 후보가 없으면 횟수를 쓰지 않는다.
- 시너지: 현재 보유 1/3/5개에서 다음 2/4/6단계를 완성하는 미보유 후보의 일반 보상 가중치만 3배. 중복 완성은 한 번만 적용한다.
- 상점: 기본 새로고침 20골드/각인 15골드, 기존 아이템 진열 슬롯 수를 유지하며 회복 상품의 상태를 보존한다. 구매는 할인 후 올림, 매각은 기준가의 50%/각인 60%를 내린다.
- 합성: 같은 등급의 서로 다른 두 재료, 골드 비용 없음. 기존 등급 확률을 먼저 적용한 후보 최대 3개 중 선택한다. 확정 시에만 교환하며 취소·재오픈·재료 순서 변경으로 결과를 다시 뽑지 않는다.

`RunItemRewardLedger`는 런의 스테이지별 최고 정상 완료 순번을 유지해 재시도 중복 보상을 막는다. `RunItemRewardInbox`는 서비스 준비·저장 복구 중의 완료 영수증을 보존한다. 후보와 남은 재선택 횟수도 같은 런에서 유지한다. 보상은 지도·인벤토리·상점·피니셔·전환과 입력/시간 소유를 공유하며 상호 배제한다.

## 검증 도구

Edit Mode에서 다음 공개 `Run()`을 실행할 수 있다. 실제 사용자 저장 파일을 수정하지 않는 메모리/임시 파일 fixture를 사용한다.

- `EngravingProgressionRegression`: v1 이관, 39개 구매/1,290 비용, 선행 조건, 재진입, 저장 실패, 백업 복구.
- `PlayerEngravingCombatRegression`: 전투 26개 노드, 확정 적중, 추가 피해, 공격 범위, I31/I50/I78 부활 반응, 과회복과 골드.
- `RunItemChoiceRegression`: 실제 59종 후보, 출격 6계통, 시너지 가중치, 재선택/보관, 빈 풀, 영수증 복구.
- `RunItemChoiceModalRegression`: 시간 소유·입력·카메라 복구, 다른 모달/피니셔/전환 배제, 건너뛰기.
- `EngravingShopRegression`: 가격 반올림, 새로고침, 회복 상품 보존, 합성 후보 고정/확정.
- `HubEngravingRegression`: 40개 선택/39개 구매, 기본 강화 유지, 상태·스크롤·저장 실패 표시.

Play Mode 시각 검증은 `EngravingVisualQA`의 격리 계정과 `BoundaryZeroReview.SetResolution`을 사용한다. 허브에서 `BeginWorkshop` → 준비 완료 → `ShowTree`/`ShowBasic`, 게임에서 `BeginIsolatedGameRun` → `GameStatus`로 실제 런 모달을 확인한다. 검증 후 `End`/`EndIsolatedGameRun`과 `RestoreResolution`으로 임시 상태를 정리한다. 앱 종료 후 진행 중인 런 저장/재개는 제공하지 않는다.

### 2026-11-08 검증 결과

Unity 6000.3.10f1에서 컴파일 오류 없이 확인했다. 새 회귀 6개 스위트 **765개 검사**와 기존 회귀 14개 스위트 **3,080개 검사**가 통과했다. 기존 검사는 강화 저장, 59종 아이템 런타임, 피해/처치 통합, 상점 경제/거래/탭, 인벤토리, 지도, 액션 타이밍, 피격 반응과 시간 소유를 포함한다. 새 검사 출력은 [regressions.txt](../EngravingIntegration/Verification/regressions.txt)에 보관했다.

실제 플레이 프레임 진행을 확인한 뒤 1280×720, 1920×1080, 2560×1080에서 트리 전체 40노드 레이캐스트와 4개 보상 카드/스크롤/선택 버튼을 검증했다. 기본 강화 화면도 914개 기하/클릭 검사를 통과했다. 확인 화면은 [Verification](../EngravingIntegration/Verification)에 있다.

격리 계정으로 출격 30골드, 실제 6계통, 단일 후보 자동 지급, 일반 방 6마리의 확정 처치 후 보상 영수증 생성, 보관·재선택·수령, 15골드 새로고침, 합성 취소/순서 변경 후 동일 후보, 확정 시 두 재료 교환과 골드 비용 0을 확인했다. 보상 수령/상점 종료 후 시간 1과 입력이 복구됐고, 보상 중 강제 사망 검사에서도 보상 모달·입력 게이트·시간 소유가 해제됐다. 테스트 계정·해상도를 정리한 후 기존 Game Scene 편집 상태로 복귀했다. 실행 파일 빌드는 이 검증에 포함하지 않았다.
