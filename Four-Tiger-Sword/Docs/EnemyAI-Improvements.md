# 적 AI 개선 설정 및 확인

## 적용 범위

- 기존 상태 머신과 공격 액션을 유지합니다.
- FanVisionSensor는 Player 태그를 가진 단일 플레이어를 캐시하고, 거리/시야각/장애물을 검사합니다. 감지 실패 시 DetectedTarget을 지웁니다. 기존 rayCount 값은 에디터 시야 표시용으로만 사용합니다.
- Enemy는 마지막 목격 위치를 기본 4초간 기억합니다. 시야를 잃으면 그 위치로 이동하고 기억 시간이 끝나면 Idle로 돌아갑니다. 생성 위치로 복귀하는 기능은 포함하지 않습니다.
- 피격 시 기존 플레이어 어그로 동작을 유지하되, 피격 순간 위치만 기억합니다.
- 접근 중 불완전/실패 경로, 이동 정체, 시간 초과를 확인하고 공격을 재선택합니다. 실패한 스킬은 잠시 선택에서 제외합니다.
- 공격 선택은 거리 선호도와 직전 공격 반복 감점을 반영한 가중치 랜덤입니다. 스킬 쿨타임과 공격 이력은 ScriptableObject가 아닌 각 Enemy에 보관합니다.
- 기존 배회 방식, 공격 회전 타이밍, 다수 적의 동시 공격 제한은 이번 변경 범위에 포함하지 않습니다.

## 일반 적의 슈퍼아머와 반격

- 공격 예고부터 마지막 타격 판정이 닫힐 때까지 HP와 강인도 피해를 받고 일반 경직·넉백을 버팁니다. 새 `EnemyAction`은 마지막 타격 처리 직후 `EndNormalAttackArmor()`를 호출합니다. 투사체 공격은 마지막 발사 직후 호출해 비행 중에도 적의 후딜을 공략할 수 있게 합니다.
- 한 번의 연속 경직 중 플레이어의 직접 타격이 세 번 경직을 일으키면 기존 공격으로 반격할 수 있습니다. 시야, 최소·실행 거리, 공통·개별 쿨타임을 모두 만족해야 하며, 경직이 풀리면 누적은 초기화됩니다. 장판·지연 피해와 추가 폭발은 횟수에서 제외합니다.
- 성공한 패링과 강인도 붕괴는 진행 중인 공격을 끊습니다. `EnemyBrainRegression.StartPlayMode()`에서 타격 종류별 보호 종료, 플레이어에게 적중하는 반격, 패링·붕괴·사망 시 정리를 검사합니다.

## Inspector 설정

### Enemy

| 설정 | 기본값 | 의미 |
|---|---:|---|
| Target Memory Duration | 4초 | 마지막으로 관측한 위치를 기억하는 시간 |
| Approach Timeout | 6초 | 공격을 선택한 뒤 접근할 수 있는 최대 시간 |
| Approach Stuck Timeout | 1.5초 | 0.1m 이상 이동하지 못하면 접근 실패 처리 |
| Failed Attack Retry Delay | 1초 | 접근 실패한 스킬의 재선택 대기 시간 |

### MonsterSkillData

| 설정 | 기본값 | 의미 |
|---|---:|---|
| minimumRange | 0m | 공격 선택/실행 가능한 최소 거리. executeRange 이하로 설정 |
| preferredRange | 0m | 선호하는 선택 거리. 0이면 executeRange 사용 |
| cooldown | 0초 | 공격 시작부터 계산하는 스킬별 쿨타임. 기존 공통 공격 쿨타임도 별도로 적용 |
| repeatWeightMultiplier | 0.5 | 직전에 사용한 스킬의 선택 가중치 배율 |

preferredRange는 minimumRange부터 engageRange 사이로 설정하는 것이 좋습니다. 돌진은 중거리, 기본 공격은 근거리를 선호하도록 조정할 수 있습니다. 쿨타임 기본값 0은 기존 공격 빈도를 보존하며, 스킬별 쿨타임이 필요하면 개별 에셋에서 설정하세요. 즉시 보스 연계는 기존처럼 선택 조건을 우회하지만 사용 이력과 쿨타임에는 기록됩니다.

FanVisionSensor의 Proximity Range는 근거리 전방위 감지 반경이며 기본값은 3m입니다. 이 안에서는 플레이어가 등 뒤로 넘어가도 시야각과 관계없이 감지합니다. 0이면 비활성화하며 전체 Range를 넘지 않습니다. 적을 선택하면 청록색 구로 표시됩니다. 비전투 상태에서도 적용되므로 은신/배후 접근이 필요한 적은 반경을 줄이세요.

FanVisionSensor의 Visibility Mask에는 시야를 막을 벽/지형 레이어를 포함하세요. 근접 감지도 같은 장애물 검사를 통과해야 합니다. 트리거는 시야를 막지 않습니다. 센서 높이에서 플레이어의 같은 높이까지 한 번의 시야 검사를 하므로 낮은 엄폐물이나 높이 차이는 씬에서 확인해야 합니다.

## 플레이 모드 확인 항목 (수동 확인 필요)

1. 기존 부채꼴 레이 사이에 플레이어를 놓아도 시야각 안이면 감지되는지 확인합니다.
2. 벽 뒤로 이동한 후 적이 마지막 목격 위치까지만 이동하고, 4초 후 Idle이 되는지 확인합니다. 다시 보이면 추적이 재개되어야 합니다.
3. 적 뒤에서 공격하면 피격 위치로 돌아서 추적하는지 확인합니다.
4. 경로가 끊긴 지형, 다른 적에 의해 막힌 통로, 계속 도주하는 플레이어를 대상으로 접근 상태가 무한 유지되지 않는지 확인합니다.
5. 근거리/중거리에서 충분한 횟수로 공격을 관찰해 선호 거리와 반복 감점이 선택 빈도에 반영되는지 확인합니다. 확률 방식이므로 같은 공격이 연속으로 나올 수 있습니다.
6. 같은 스킬 에셋을 쓰는 적 두 마리 중 하나의 공격이 다른 적의 스킬 쿨타임에 영향을 주지 않는지 확인합니다.
7. 피격/그로기/사망에 의한 공격 중단과 보스 즉시 연계가 기존처럼 동작하는지 확인합니다.
8. 플레이어가 적 뒤 2m에 있으면 감지하고, 뒤 4m에서는 전방 시야 밖이므로 감지하지 않는지 확인합니다. 전방 4m는 기존 시야대로 감지해야 합니다.
9. 뒤 2m라도 사이에 벽이 있으면 감지가 차단되는지, Proximity Range를 0으로 설정하면 전방 시야만 사용하는지 확인합니다.

## 수행한 검증

Unity 6000.3.10f1의 Roslyn 컴파일러와 프로젝트의 Assembly-CSharp 응답 파일을 사용해 전체 게임 코드 컴파일을 확인했습니다. 결과물은 임시 폴더에 출력해 Unity의 기존 DLL을 덮어쓰지 않았습니다. 컴파일 성공, 기존 PoiseHandler.OnPoiseBreak 미사용 이벤트 경고 1건입니다. 플레이 모드 동작과 프리팹별 튜닝은 아직 검증하지 않았습니다.

## 보스 전용 전투 프로필 설정

이 기능은 페이즈별로 선택해서 적용합니다. 위의 센서·기억·접근 설정은 일반 몬스터와 기존 방식의 보스에 적용됩니다. `BossPhaseData.combatProfile`이 비어 있으면 기존 보스 행동을 사용하며, 현재 `Test_Boss`의 프리팹과 세 페이즈 설정은 변경하지 않습니다.

1. Project 창에서 **Create > SainGum > Monster > Boss Combat Profile**로 전투 프로필을 만듭니다.
2. **Create > SainGum > Monster > Boss Tactical Pattern**으로 연계 패턴을 만들고 프로필의 `Patterns`에 등록합니다. 기존 `Boss Sequence Pattern`도 등록할 수 있습니다.
3. 각 옵션의 `Condition`에서 거리, 보스 전방 기준 각도(0~180도), 현재 페이즈 HP 비율, 가시성, 준비되어야 할 스킬을 설정합니다. `Visibility` 기본값 `Any`는 장애물을 선택 조건에 사용하지 않습니다. `Visible`/`Occluded`는 대상과 보스 사이의 장애물만 검사하며 시야각을 적용하지 않습니다.
4. 적용할 `BossPhaseData`의 `Combat Profile`에 프로필을 연결합니다. 현재 페이즈 HP를 모두 소진한 뒤 다음 페이즈로 부활하는 기존 전환 방식은 유지됩니다. 조건의 HP 비율은 해당 페이즈 체력에 대한 비율입니다.

프로필을 사용하는 보스는 활성화 시점부터 전투 중입니다. 탐색·순찰·마지막 목격 위치 추적 상태를 거치지 않습니다. Inspector의 **전술 전투 대상**에 연결하거나 조우 코드에서 `boss.SetCombatTarget(playerTransform)`으로 지정합니다. 비워 두면 `Player` 태그의 대상을 연결해 계속 유지합니다. 대상이 비활성화되거나 사망하면 공격과 이동을 중단하고 대기하며, `SetCombatTarget(null)`은 새 대상이 명시적으로 지정될 때까지 대기시킵니다. 장애물은 전투 대상을 잃게 하지 않습니다.

### 단계와 분기

패턴의 `Steps` 인덱스는 0부터 시작합니다. `Attack`은 기존 스킬을 실행하고, `Wait`는 대기, `Move`는 접근·거리 유지·후퇴·좌우 이동, `Recover`는 공격하지 않는 회복 구간입니다. `Branch`는 이전 행동이 끝난 시점의 전투 상황으로 다음 단계를 정합니다. 진행 중인 타격을 매 프레임 다른 패턴으로 바꾸지 않습니다.

`Next`는 일반 단계의 다음 위치이고, `Next If True`/`Next If False`는 분기의 목적지입니다. **-2는 다음 인덱스, -1은 패턴 종료, 0 이상은 지정한 단계 인덱스**입니다. 예를 들어 돌진 → 거리 2m 이내인지 분기 → 근접 후속타 또는 종료로 구성할 수 있습니다. 첫 단계가 공격이면 실행 사거리에 들어온 뒤 선택하며, 이동으로 시작하는 패턴은 사거리 밖에서도 선택할 수 있습니다. 후속 스킬이 쿨타임이거나 실행 범위 밖이면 무한히 기다리지 않고 패턴을 끝내고 회복합니다.

프로필에서는 패턴 에셋의 기존 `Loop` 값과 관계없이 한 순회를 실행한 뒤 다시 조건과 쿨타임으로 선택합니다. 패턴 내부의 분기 그래프에는 `Max Command Steps` 한도가 있으며, 시간 경과 없이 반복되는 분기·0초 대기·0초 회복 순환은 작성 오류로 표시합니다.

### 조준·강인도·시간 설정

각 공격 단계의 `Attack Policy > Enabled`를 켜면 보스 전용 규칙을 적용합니다. `Turn Speed`는 준비 중 회전 속도, `Lock Fraction`은 준비 시간 중 조준을 확정하는 비율입니다. 콤보는 각 타격의 준비 구간에서 제한적으로 다시 조준하고, 돌진 방향과 점프 착지점은 확정 이후 바뀌지 않습니다. `Armor During Startup`/`Armor During Active`는 해당 구간의 일반 피격 경직과 넉백만 막으며 피해·포이즈 누적과 그로기·패링 등의 중단은 유지됩니다. 공격 후 회복 구간에는 임시 강인도를 적용하지 않습니다.

정책이 없거나 `Enabled`가 꺼져 있으면 기존 공격 실행 방식을 사용합니다. [Unity 인라인 직렬화는 null 클래스를 객체로 복원할 수 있으므로](https://docs.unity3d.com/kr/current/ScriptReference/SerializeReference.html), Inspector에서는 객체 유무 대신 이 토글로 적용 여부를 정합니다. 활성화된 정책은 기본 공격·콤보·돌진·점프 내리찍기에 지원되며, 사용자 정의 스킬에는 비활성 상태로 두거나 별도의 실행 지원을 추가해야 합니다. 스킬 에셋 자체는 수정하지 않으므로 일반 몬스터와 같은 에셋을 공유할 수 있습니다.

프로필 실행에는 일반 몬스터의 공통 `Attack Cooldown`을 추가하지 않습니다. 공격에 포함된 후딜, 패턴의 `Recover`, 옵션의 `Recovery`를 합산해 실제 빈틈을 조정합니다. 옵션의 `Cooldown`은 패턴 선택 시점부터, 개별 스킬의 `cooldown`은 공격 시작 시점부터 계산하며 각 보스가 별도로 보관합니다. 준비·공격·회복·이동 진행은 보스의 actor 시간을 사용하고, 쿨타임은 기존처럼 월드 시간을 사용합니다. 패턴 실패 시 옵션의 `Recovery`와 `Failure Recovery` 중 긴 시간을 적용하고, 패턴 밖 위치 조정 실패에는 `Failure Recovery`, 패링에는 `Parry Recovery`를 적용합니다.

### 작성 오류와 실행 상태 확인

프로필·전술 패턴 Inspector는 누락된 에셋, 잘못된 분기 인덱스, 음수/비정상 시간, 뒤집힌 거리 범위, 지원하지 않는 활성 정책과 잘못된 타격 시간을 오류로 표시합니다. 플레이 모드에서 보스 Inspector의 **보스 전투 상태 (읽기 전용)**를 열면 대상, 페이즈, 현재 상태·패턴·단계, 판단 이유, 최근 실패를 확인할 수 있습니다.

보스 전용 검증 진입점은 `BossTacticalRegression.Run()`(작성 데이터)과 `BossTacticalRegression.StartPlayMode()`/`PlayModeStatus()`(실행 동작)입니다. 위의 일반 몬스터 검증 기록과 별도로 실행합니다. 회복 중 피격·그로기·속박으로 상태가 바뀌어도 남은 회복 시간은 복귀 후 이어져 반격 가능 시간이 짧아지지 않습니다. 비활성화·페이즈 전환·최종 사망은 이 시간을 초기화합니다.

### 사용자 정의 공격의 보스 정책 지원

기본 공격·콤보·돌진·점프 내리찍기와 그 파생 SO는 정책 지원을 선언합니다. 별도의 사용자 정의/생성 공격은 SO에서 `public override bool SupportsBossExecutionPolicy => true;`, 실행 액션에서 `public override bool SupportsBossPolicy => true;`를 모두 구현해야 합니다. SO 선언은 작성 데이터 검사에, 액션 선언은 실제 실행 전 검사에 사용합니다. 지원 선언만 추가하지 말고 아래 실행 규칙도 연결해야 합니다. 정책이 꺼져 있으면 이 선언 없이 기존 공격을 사용할 수 있습니다.

- `ConfigureBossPolicy()`가 정책을 실행 액션에 복사하고, `base.Enter()`는 준비·조준 상태를 초기화합니다. `BossInitialStartupDuration`을 실제 첫 준비 시간으로 재정의하면 준비 시간이 0인 공격도 진입 즉시 Active 상태를 표시합니다. 여러 타격으로 이루어진 공격은 다음 타격의 준비 구간 시작에 `BeginBossPreparation()`을 호출합니다.
- 준비 갱신에서 `TickBossPreparation(previousTime, currentTime, startupStart, activeStart)`를 호출합니다. 시간은 기존 액션 타이머처럼 `ActionDeltaTime * attackSpeed` 기준입니다. 이 헬퍼가 제한 회전과 조준 확정, Startup/Active 상태를 처리합니다. 실제 돌진·투사체 발사에는 `BossAimDirection`, 착지점에는 `BossAimPoint`를 사용해 확정 이후 대상을 다시 추적하지 않도록 합니다. `HasBossPolicy`가 꺼져 있으면 기존 조준 방식을 유지합니다.
- 공격 유효 구간에는 `SetBossStage(BossAttackStage.Active)`, 후딜에는 `SetBossStage(BossAttackStage.Recovery)`를 호출합니다. `HasBossArmor`는 현재 구간과 정책의 설정에 따라 계산되며, 패링 직후에는 바로 꺼집니다. `base.Exit()`이 완료·비활성 상태와 조준 고정 표시, 임시 강인도, 패링 예고를 정리합니다. 파생 액션은 자신이 획득한 이동 잠금·충돌체·내비게이션 상태도 해제해야 합니다.
- `base.Enter()`/`base.Update()` 이후와 피해 등 외부 콜백 직후에 `if (!CanContinueBossAction) return;`을 확인합니다. 전술 보스 또는 활성 정책의 액션이 콜백에서 교체·패링·중단되면 같은 프레임의 나머지 타격을 중단해야 합니다. 피해의 `source`에는 래퍼가 아닌 실제 `EnemyAction`인 `this`를 전달합니다.

`BossAttackPolicy.ValidateSkill(skill)`은 정책 활성화와 무관하게 기본 공격 계열의 타이밍·이동 값을 검사하며, 파생 SO에도 같은 검사를 적용합니다. 별도 사용자 정의 공격의 추가 매개변수는 해당 공격의 작성 도구나 패턴의 `Validate()`에서 검사해야 합니다. 공유 SO에는 실행 타이머·현재 조준·액션 소유자를 저장하지 않습니다.

아래 시간은 공격 속도 1일 때의 공격 타임라인입니다. 2페이즈 연격은 1.12배, 차징 모션은 1.08배 속도입니다. `Charge Seconds`는 공격 속도와 별도로 액터 시간에 따라 흐릅니다.

차징은 일반 경직을 버티지만 **준비/유지 중 유효한 넉백을 받으면 공격을 취소하고 그로기**가 됩니다. 준비·타격 아머 중에도 HP·강인도 피해와 패링은 유지됩니다. 돌진의 보스 몸 충돌체도 유지되므로 돌진 중 피해와 강인도 붕괴가 가능합니다. 기본 공격의 `Startup Anim Name`/`Animation Start Delay`, 돌진의 `Startup Anim Name`은 선택적이며 비어 있으면 기존 몬스터 동작을 유지합니다.

### 모델·애니메이션

기존 `BossMonster_Rigged` 모델과 `BossWeapon_3m` 대검, Nephilite의 Remastered 양손검 클립을 사용합니다. 모델 원본 아바타는 휴머노이드 재생 스케일이 맞지 않아, 실제 골격 스케일과 T 자세에서 **별도의 보스 아바타**를 생성합니다. 원본 모델 importer는 바꾸지 않습니다. 생성된 보스 클립은 반복을 끄고 이벤트를 제거하며, 원본의 루트 이동 추출 설정을 보존합니다. 로봇 어깨 비율에 맞춘 양손 IK와 손가락 잡기, 검 궤적, 바닥 예고가 전용 프리팹에 포함됩니다.

플레이어의 실제 `BDJ.controller`에는 누락된 `Knockdown`/`GetUp` 상태만 추가합니다. 기존 다운·기상 클립을 사용하고 타격별 다운/기상 시간에 맞게 재생합니다. 회피·패링에 성공한 타격은 다운을 일으키지 않습니다.

### 재생성·검증

`Tools > SainGum > Sword Robot Boss > Build and Apply to Current Run`은 전용 폴더의 설정을 초기 작성값으로 다시 만들고 현재 런을 연결합니다. Inspector에서 튜닝한 뒤에는 이 메뉴로 덮어쓰지 말고 해당 에셋을 직접 저장합니다.

- `SwordRobotBossRegression.Run()`: 프리팹·페이즈·스킬·아바타·무기·현재 런·플레이어 다운 모션 구성 검사.
- Play Mode의 `SwordRobotBossRegression.StartPlayMode()`/`PlayModeStatus()`: 격리한 실제 액터로 차징 약점, HP/강인도, 연격 3타 다운·기상·회피·패링, 조준 고정, 정리, 단일 부활 검증.
- Game Scene Play Mode의 `SwordRobotBossLiveRegression.StartPlayMode()`/`PlayModeStatus()`: 실제 생성된 보스방에서 전투·부활·최종 처치·문·보상·HUD를 검증하고 `Temp/SwordRobotBossLive`에 보고서와 캡처를 남깁니다. 해당 테스트는 플레이 중 조우를 소비하므로 새 실행에서 사용합니다.

신규 작성 검사 30개와 격리 실행 검사 40개가 통과했습니다. 기존 전술 실행 86개, 일반 몬스터·보스 Brain 124개, HUD 85개, 보스 전투 43개, 페이즈 35개, 보상 17개, 음악 16개, 전술 작성 16개도 통과했습니다.

실제 Game Scene의 생성된 보스방에서도 새 프리팹 소환, 자율 공격 예고, 1회 부활, 2페이즈 체력 복구, 최종 사망 1회, 150골드 지급, 문 개방, HUD 종료와 음악 유지가 통과했습니다. 부활 설정 5.484초에 대해 액터 시간 측정값은 약 5.489초였습니다. Console 오류와 컴파일 오류 없이 종료하고 원래 Hub Scene의 Edit Mode로 복원했습니다. 밸런스 수치는 Inspector에서 추가 조정할 수 있습니다.
