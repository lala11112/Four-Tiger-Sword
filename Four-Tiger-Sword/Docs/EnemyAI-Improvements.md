# 적 AI 개선 설정 및 확인

## 적용 범위

- 기존 상태 머신과 공격 액션을 유지합니다.
- FanVisionSensor는 Player 태그를 가진 단일 플레이어를 캐시하고, 거리/시야각/장애물을 검사합니다. 감지 실패 시 DetectedTarget을 지웁니다. 기존 rayCount 값은 에디터 시야 표시용으로만 사용합니다.
- Enemy는 마지막 목격 위치를 기본 4초간 기억합니다. 시야를 잃으면 그 위치로 이동하고 기억 시간이 끝나면 Idle로 돌아갑니다. 생성 위치로 복귀하는 기능은 포함하지 않습니다.
- 피격 시 기존 플레이어 어그로 동작을 유지하되, 피격 순간 위치만 기억합니다.
- 접근 중 불완전/실패 경로, 이동 정체, 시간 초과를 확인하고 공격을 재선택합니다. 실패한 스킬은 잠시 선택에서 제외합니다.
- 공격 선택은 거리 선호도와 직전 공격 반복 감점을 반영한 가중치 랜덤입니다. 스킬 쿨타임과 공격 이력은 ScriptableObject가 아닌 각 Enemy에 보관합니다.
- 기존 배회 방식, 공격 회전 타이밍, 다수 적의 동시 공격 제한은 이번 변경 범위에 포함하지 않습니다.

## Inspector 설정

### Enemy

| 설정 | 기본값 | 의미 |
|---|---:|---|
| Target Memory Duration | 4초 | 마지막으로 관측한 위치를 기억하는 시간 |
| Approach Timeout | 6초 | 공격을 선택한 뒤 접근할 수 있는 최대 시간 |
| Approach Stuck Timeout | 1.5초 | 0.1m 이상 이동하지 못하면 접근 실패 처리 |
| Failed Attack Retry Delay | 1초 | 접근 실패한 스킬의 재선택 대기 시간 |

### MonsterSkillData

| 설정 | 기본값 | 의미 |
|---|---:|---|
| minimumRange | 0m | 공격 선택/실행 가능한 최소 거리. executeRange 이하로 설정 |
| preferredRange | 0m | 선호하는 선택 거리. 0이면 executeRange 사용 |
| cooldown | 0초 | 공격 시작부터 계산하는 스킬별 쿨타임. 기존 공통 공격 쿨타임도 별도로 적용 |
| repeatWeightMultiplier | 0.5 | 직전에 사용한 스킬의 선택 가중치 배율 |

preferredRange는 minimumRange부터 engageRange 사이로 설정하는 것이 좋습니다. 돌진은 중거리, 기본 공격은 근거리를 선호하도록 조정할 수 있습니다. 쿨타임 기본값 0은 기존 공격 빈도를 보존하며, 스킬별 쿨타임이 필요하면 개별 에셋에서 설정하세요. 즉시 보스 연계는 기존처럼 선택 조건을 우회하지만 사용 이력과 쿨타임에는 기록됩니다.

FanVisionSensor의 Proximity Range는 근거리 전방위 감지 반경이며 기본값은 3m입니다. 이 안에서는 플레이어가 등 뒤로 넘어가도 시야각과 관계없이 감지합니다. 0이면 비활성화하며 전체 Range를 넘지 않습니다. 적을 선택하면 청록색 구로 표시됩니다. 비전투 상태에서도 적용되므로 은신/배후 접근이 필요한 적은 반경을 줄이세요.

FanVisionSensor의 Visibility Mask에는 시야를 막을 벽/지형 레이어를 포함하세요. 근접 감지도 같은 장애물 검사를 통과해야 합니다. 트리거는 시야를 막지 않습니다. 센서 높이에서 플레이어의 같은 높이까지 한 번의 시야 검사를 하므로 낮은 엄폐물이나 높이 차이는 씬에서 확인해야 합니다.

## 플레이 모드 확인 항목 (수동 확인 필요)

1. 기존 부채꼴 레이 사이에 플레이어를 놓아도 시야각 안이면 감지되는지 확인합니다.
2. 벽 뒤로 이동한 후 적이 마지막 목격 위치까지만 이동하고, 4초 후 Idle이 되는지 확인합니다. 다시 보이면 추적이 재개되어야 합니다.
3. 적 뒤에서 공격하면 피격 위치로 돌아서 추적하는지 확인합니다.
4. 경로가 끊긴 지형, 다른 적에 의해 막힌 통로, 계속 도주하는 플레이어를 대상으로 접근 상태가 무한 유지되지 않는지 확인합니다.
5. 근거리/중거리에서 충분한 횟수로 공격을 관찰해 선호 거리와 반복 감점이 선택 빈도에 반영되는지 확인합니다. 확률 방식이므로 같은 공격이 연속으로 나올 수 있습니다.
6. 같은 스킬 에셋을 쓰는 적 두 마리 중 하나의 공격이 다른 적의 스킬 쿨타임에 영향을 주지 않는지 확인합니다.
7. 피격/그로기/사망에 의한 공격 중단과 보스 즉시 연계가 기존처럼 동작하는지 확인합니다.
8. 플레이어가 적 뒤 2m에 있으면 감지하고, 뒤 4m에서는 전방 시야 밖이므로 감지하지 않는지 확인합니다. 전방 4m는 기존 시야대로 감지해야 합니다.
9. 뒤 2m라도 사이에 벽이 있으면 감지가 차단되는지, Proximity Range를 0으로 설정하면 전방 시야만 사용하는지 확인합니다.

## 수행한 검증

Unity 6000.3.10f1의 Roslyn 컴파일러와 프로젝트의 Assembly-CSharp 응답 파일을 사용해 전체 게임 코드 컴파일을 확인했습니다. 결과물은 임시 폴더에 출력해 Unity의 기존 DLL을 덮어쓰지 않았습니다. 컴파일 성공, 기존 PoiseHandler.OnPoiseBreak 미사용 이벤트 경고 1건입니다. 플레이 모드 동작과 프리팹별 튜닝은 아직 검증하지 않았습니다.
