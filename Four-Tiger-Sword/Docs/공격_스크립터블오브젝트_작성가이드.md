# 공격 ScriptableObject 작성 가이드

이 문서는 현재 프로젝트 코드 기준으로 공격 에셋을 만드는 방법과 인스펙터 입력값을 설명합니다. 기획 명세의 목표 수치와 기존 에셋 값이 모두 같지는 않습니다. 아래 예시는 새 공격을 작성하기 위한 예시이며 기존 에셋을 덮어쓰라는 뜻이 아닙니다.

## 1. 먼저 알아둘 구조

**폼 하나에 `WeaponActionDataSO` 에셋 하나를 연결합니다.** 그 안에 일반 공격, 스킬, 궁극기, 반격 데이터를 넣습니다.

| 구성 | 의미 |
|---|---|
| `WeaponActionDataSO` | 한 폼의 공격 데이터 묶음. Project 창에서 만드는 `.asset` 파일 |
| `WeaponActionData` | 공격 한 단계. 에셋 내부의 목록 항목으로 작성 |
| `HitEvent` | 한 단계 안에서 발생하는 개별 타격 |
| `FireForm`, `WaterForm` 등 | 데이터를 실행하고 속성 고유 효과를 처리하는 C# 코드 |

예를 들어 일반 공격이 3번의 입력으로 6회 타격한다면 `Combo Steps`는 3개, 각 항목의 `Hit Events`는 2개입니다. `Combo Steps`를 6개로 만들면 입력 단계 자체가 6개가 됩니다.

## 2. 에셋 만들기

1. Unity Project 창에서 `Assets/_Project/Scripts/FormActions` 폴더를 선택합니다.
2. 우클릭 → **Create → Combat → Weapon Attack Data**를 선택합니다.
3. 파일 이름을 지정합니다. 예: `IronFormAction_V2`.
4. 인스펙터에서 아래 항목들을 채웁니다.

현재 에셋을 바탕으로 조정하려면 해당 에셋을 복제하는 방법도 있습니다. 기존 폼에 필요한 특수 설정과 효과 참조를 유지하기 쉽습니다. 복제 후에는 플레이어의 연결도 새 에셋으로 바꿔야 합니다.

현재 사용 중인 파일:

| 폼 | 파일 |
|---|---|
| 화 | `FireFormAction.asset` |
| 수 | `WaterFromAction.asset` — 현재 파일명은 **From**입니다 |
| 목 | `WoodFormAction.asset` |
| 금 | `IronFormAction.asset` |
| 토 | `EarthFormAction.asset` |

## 3. 새 에셋에서 반드시 채울 항목

| 항목 | 넣을 내용 |
|---|---|
| `Weapon Name` | 알아보기 위한 이름. 예: `Iron`. 속성이나 폼 클래스를 결정하는 값은 아닙니다 |
| `Combo Steps` | 최소 1개 이상의 유효한 일반 공격 단계 |
| `Skill Steps` | 최소 1개 이상의 유효한 스킬 단계 |
| `Ultimate Steps` | 최소 1개 이상의 유효한 궁극기 단계. 물·토도 비워두지 마세요 |
| `Counter Step` | 반격 데이터. 기본 생성값을 그대로 두지 말고 피해 배율 등을 지정 |
| `Air Attack Step` | 공중 내려찍기를 사용할 경우 착지 후 공격 데이터 |

**각 단계의 `Duration`은 0보다 크게 지정하세요.** 현재 시작 처리에서 첫 항목에 바로 접근하는 경로가 있어, 비어 있는 목록은 기능 비활성화 용도로 사용할 수 없습니다. 폼 연결을 `None`으로 두는 방식도 지원하지 않습니다.

동작을 임시로 비우려면 테스트용 에셋을 따로 만들고, 유효한 길이의 단계와 0개의 실제 타격을 구성하세요. 예를 들어 `Duration = 0.5`, `Hit Duration = 0`, `Hit Events = 0개`, `Thrust Multiplier = 0`으로 설정할 수 있습니다. 다만 스킬에 연결된 별도 폭발·장판 등 코드 효과는 이 설정만으로 꺼지지 않습니다.

## 4. 공격 한 단계의 입력값

### 4-1. 모션과 시간

| 항목 | 의미와 입력 방법 |
|---|---|
| `Animation Name` | Animator의 **State 이름**. 트리거 파라미터 이름이 아닙니다. 현재 코드는 레이어 0의 State 존재 여부를 확인합니다 |
| `Duration` | 해당 단계의 전체 길이. 단위는 초 |
| `Combo Transition Time` | 일반 공격에서 다음 콤보로 넘어갈 수 있는 시점 |

애니메이션이 없으면 `Animation Name`을 **빈칸**으로 두세요. 일반 공격·스킬·궁극기·반격의 공통 재생 함수는 빈 이름을 건너뛰며, 시간과 타격 판정은 진행합니다. 새 모션 연결 예시는 코드에 `TODO`와 주석으로 남아 있습니다. 기존에 연결된 유효한 모션은 계속 재생됩니다.

공중 공격은 별도 상태 흐름을 사용하므로 `Air Attack Step.Animation Name`만 입력한다고 공통 함수가 자동으로 재생하지는 않습니다. 공중 모션을 추가할 때는 `PlayerAirAttackState`와 `BeginAirAttack()`도 확인해야 합니다.

일반 공격의 타이머는 대체로 다음처럼 진행됩니다.

```text
공격 시간 += 프레임 시간 × 공격속도 배율
```

따라서 인스펙터 시간은 공격속도 1배 기준입니다. 공격속도가 2배라면 `Hit Start Time = 0.4`의 판정은 약 0.2초 후에 발생합니다. 히트스탑 동안에는 게임 시간이 정지하거나 느려집니다.

60FPS 기준 기획 프레임을 초로 옮길 때:

```text
초 = 프레임 수 / 60
8f = 0.1333초
12f = 0.2초
20f = 0.3333초
30f = 0.5초
```

`Combo Transition Time`은 일반적으로 다음 조건을 만족하도록 설정합니다.

```text
마지막 타격 종료 시점 ≤ Combo Transition Time < Duration
```

현재는 입력 버퍼가 살아 있고 전환 시점이 지났으면 바로 다음 타로 넘어갑니다. 타격보다 이르게 지정하면 다음 입력 때문에 현재 타수가 잘릴 수 있습니다. 마지막 콤보 항목은 다음 항목이 없으므로 이 값으로 후속 타가 생기지 않습니다.

### 4-2. 피해와 단타 판정

| 항목 | 실제 코드에서의 의미 |
|---|---|
| `Damage` | **플레이어 공격력에 곱할 배율**. 1.5배 공격은 `1.5` 입력 |
| `Poise Damage` | 적 강인도에 가하는 수치 |
| `Hit Start Time` | 단계 시작 후 판정을 시작할 시간 |
| `Hit Duration` | 판정 유지 시간. 실제로 맞히려면 0보다 크게 설정 |
| `Knockback Force` | 넉백 기준 힘. 현재는 공격력 보정과 적 저항도 반영되므로 이동 거리와 같지 않음 |
| `Stagger Resist Level` | 타격이 적을 경직시킬 수 있는 등급. 적의 저항 등급과 비교됨 |

기본 피해 계산 예:

```text
플레이어 공격력 100 × Damage 1.5 = 기본 피해 150
```

일반 피해에는 이후 속성 상성, 치명타, 적 방어력이 적용됩니다. 금 궁극기의 고정 피해는 예외입니다.

`Damage` 기본 생성값이 10인 경우 이는 피해 10이 아니라 **공격력의 10배**입니다. 새 에셋의 기본값을 반드시 확인하세요.

단타 공격은 `Hit Events`를 비워두고 아래처럼 설정합니다.

```text
Duration:               0.6
Damage:                 1.0
Hit Start Time:         0.2
Hit Duration:           0.1
Combo Transition Time:  0.4
```

0.2~0.3초 사이에 같은 적에게 한 번 피해를 줍니다. 판정 구간 전체를 한 프레임에 건너뛰어도 시간 구간 교차를 검사합니다. 다만 과거 위치를 재현하는 것은 아니며, 일반 공격의 공간 판정은 검사 당시 위치를 사용합니다.

### 4-3. 다단히트: Hit Events

**`Hit Events`가 1개 이상이면 기본 `Hit Start Time / Hit Duration` 대신 이벤트 목록을 사용합니다.**

| 이벤트 항목 | 넣을 값 |
|---|---|
| `Start Time` | 해당 타격 시작 시점. 단계 시작 기준 초 |
| `Duration` | 해당 타격 판정 길이. 0보다 크게 지정 |
| `Damage` | 타격별 피해 배율. 0 이하이면 단계의 `Damage`를 사용 |
| `Poise Damage` | 타격별 강인도 피해. 0 이하이면 단계의 `Poise Damage`를 사용 |
| `Stagger Resist Level` | 필드는 있으나 **현재 개별 이벤트 값은 실행 코드에 반영되지 않음**. 단계의 값을 설정하세요 |

2회 베기 예:

| 이벤트 | Start Time | Duration | Damage |
|---|---:|---:|---:|
| Element 0 | 0.1333 | 0.04 | 0.6 |
| Element 1 | 0.2167 | 0.04 | 0.6 |

`Duration`은 예를 들어 0.6초, `Combo Transition Time`은 0.35초로 둡니다. 이벤트마다 같은 적을 한 번씩 맞힐 수 있으므로 총 2회입니다. 같은 이벤트가 적의 여러 콜라이더와 겹쳐도 피해 수신 객체 기준으로 중복을 막습니다.

모든 이벤트가 단계 전체 시간 안에 들어오게 작성하고, 빈 이벤트 항목은 만들지 마세요. 이벤트 하나만 강인도 피해를 0으로 만들고 싶어도 현재 0은 기본값 사용 의미이므로, 그 경우에는 단계의 `Poise Damage`도 확인해야 합니다.

### 4-4. 히트박스

| 항목 | 의미 |
|---|---|
| `Hit Box Offset` | 플레이어 위치 기준 오프셋. X는 옆, Y는 위, Z는 전방이며 플레이어 회전을 따라감 |
| `Hit Box Shape` | Sphere / Box / Capsule 중 선택 |
| `Hit Box Radius` | Sphere·Capsule의 반지름 |
| `Hit Box Size` | Box의 **반쪽 크기(half extents)** |
| `Hit Box Height` | Capsule의 전체 높이. `2 × Radius` 이상으로 설정 |

박스의 실제 너비·높이·길이를 1.2m × 2m × 4m로 만들려면 `Hit Box Size = (0.6, 1, 2)`를 입력합니다. 현재 코드는 값을 `OverlapBox`에 그대로 전달하며, 기즈모도 2배 크기로 그립니다.

Capsule은 플레이어의 위쪽 축을 따라 선 형태로 만들어집니다. 전방으로 긴 찌르기는 Box와 전방 오프셋을 사용하는 편이 현재 구조에 맞습니다.

적 피격용 Collider가 있는 오브젝트의 Layer는 `Enemy`여야 합니다. `IDamageable` 구현 컴포넌트는 해당 오브젝트 또는 부모에 있어야 합니다. 콜라이더만 추가하고 Layer를 다른 값으로 두면 검색되지 않습니다.

### 4-5. 전진 커브

| 항목 | 의미 |
|---|---|
| `Thrust Curve` | X축: 공격 전체의 진행률 0~1. Y축: 전진 속도 비율 |
| `Thrust Multiplier` | 커브 값에 곱하는 속도 계수 |

```text
이번 프레임 이동량 = 커브 값 × Thrust Multiplier × 프레임 시간
```

**Multiplier는 최대 이동 거리가 아닙니다.** 커브 아래 면적과 공격 길이에 따라 총 이동량이 달라집니다. 고정 위치 공격을 먼저 만들려면 `Thrust Multiplier = 0`으로 시작하세요. 전진을 추가할 때는 공격 초반에만 양수인 커브를 쓰고, 키 사이의 곡선이 의도치 않게 솟거나 음수가 되지 않는지 확인하세요.

커브가 음수면 후진할 수 있습니다. 기본값인 0짜리 커브는 Multiplier만 올려도 전진하지 않습니다. 현재 공격속도와 전진 거리가 완전히 독립적이지 않으므로, 공격속도 버프까지 고려한 거리 보정이 필요하면 코드 개선 범위입니다.

### 4-6. Soft Target Approach

현재 이 설정은 **일반 콤보에서, 타수 시작 시 타깃을 찾았을 때** 적용됩니다. 스킬 돌진이나 물·토의 특수 궁극기 이동을 설정하는 항목은 아닙니다.

| 항목 | 시작용 값 | 의미 |
|---|---:|---|
| `Use Target Approach` | 켜짐 | 적이 있을 때 전진을 제한 |
| `Stop Distance` | 0.25 | 플레이어 몸체와 적 Collider 표면 사이의 간격(m) |
| `Approach End Time` | 첫 타격 시작 시간 | 자동 전진 종료 시점 |
| `Rotation End Time` | 첫 타격 시작 시간 | 자동 방향 보정 종료 시점 |
| `Max Approach Distance` | 2 | 타수당 자동 전진 최대 거리(m) |

타수마다 전방 타깃을 다시 선택합니다. 이 기능은 새 추진력을 만드는 것이 아니라 **기존 커브 이동을 줄이거나 멈추는 기능**입니다. 커브가 0이면 멀리 있는 적에게 자동으로 달려가지 않습니다.

타깃이 없으면 기존 커브대로 움직이며, `Max Approach Distance`가 허공 공격의 이동까지 제한하지는 않습니다. 적이 있는데 너무 바짝 붙으면 `Stop Distance`를 늘리고, 너무 오래 따라가면 종료 시간을 줄이세요.

### 4-7. 이펙트와 소리

| 위치 | 항목 | 역할 |
|---|---|---|
| 각 단계 | `Slash VFX` | 일반 콤보·스킬·궁극기 단계가 시작할 때 생성할 프리팹 |
| 각 단계 | `Swing Sound` | 해당 단계 시작 시 재생할 휘두르기 소리 |
| 에셋 공통 | `Hit VFX` | 공통 적중 처리에서 생성할 이펙트 |
| 에셋 공통 | `Hit Sound` | 공통 적중 소리 |
| 에셋 공통 | `Delayed Hit VFX` | 현재 물 스킬의 지연 타격에 사용 |

없으면 `None`으로 둡니다. `Slash VFX`는 `Hit Start Time`에 맞춰 지연 생성되는 항목이 아닙니다. 공중 공격·반격 및 별도 범위 효과는 공통 단계 시작/적중 함수를 모두 통과하지 않으므로, 이 필드만 연결해서 모든 연출이 자동으로 생기는 것은 아닙니다.

## 5. 일반 공격·스킬·궁극기의 차이

| 데이터 | 진행 방식 |
|---|---|
| `Combo Steps` | 공격 입력 버퍼와 전환 시간에 따라 다음 단계로 연결 |
| `Skill Steps` | 공통 처리에서는 `Duration`이 끝나면 다음 단계로 자동 진행 |
| `Ultimate Steps` | 공통 처리에서는 다음 단계로 자동 진행. 물·토는 전용 구현 사용 |
| `Counter Step` | 반격 상태에서 단일 단계 실행 |
| `Air Attack Step` | 내려찍기 착지 후 판정에 사용 |

물 스킬은 현재 단일 돌진 단계를 전제로 경로 타격을 추가했습니다. 물 스킬에 여러 단계를 새로 넣거나 물·토 궁극기의 타수를 바꾸려면 목록 편집만 하지 말고 해당 폼 코드를 함께 수정해야 합니다.

## 6. 폼별 별도 설정과 코드 고정값

### 에셋 상단에서 조절 가능한 공통 값

| 항목 | 현재 설정 | 사용처 |
|---|---:|---|
| `Fire Explosion Delay` | 0.15초 | 화 폼 6스택 추가 피해의 지연 시간. 실제 시간 기준으로 히트스탑의 영향을 받지 않으며, 0이면 즉시 적용 |
| `Ultimate Cooldown` | 화 30 / 수 25 / 목 35 / 금 30 / 토 40초 | 궁극기 시작 시 쿨타임 발생. 다른 폼으로 바꿔도 진행 |
| `Area Radius` | 4m | 화 지연 폭발, 물 궁극기, 목 장판·치유 영역, 토 궁극기 |
| `Field Duration` | 5초 | 목 독 장판·치유 영역 |
| `Heal Max Hp Per Second` | 0.05 | 목 치유 영역에서 초당 최대 HP의 5% 회복 |
| `Shield Amount` | 300 | 토 스킬 보호막 흡수량 |
| `Shield Duration` | 5초 | 토 스킬 보호막 유지 시간 |

장판 반경·시간·치유량·보호막량은 기획서에 확정 수치가 없어 둔 임시값입니다. 모든 공통 필드가 모든 폼에 적용되는 것은 아닙니다. 예를 들어 토 스킬의 **충격파 범위**는 `Skill Steps` 안의 히트박스를 바꿔야 하고, `Area Radius`만 바꿔서는 달라지지 않습니다.

`FireFormAction.asset`의 `Fire Stack Explosion > Fire Explosion Delay`에서 조절합니다. 6스택은 마지막 타격 즉시 소모하고, 추가 피해와 그 피해 숫자는 설정한 시간 뒤 발생합니다. 대기 중에도 다음 스택을 쌓을 수 있고, 적이 죽거나 비활성화되면 예약된 폭발은 취소됩니다. 화 스킬의 별도 1초 지연 폭발에는 영향을 주지 않습니다.

## 7. 완성 예시: 금 폼 기본 찌르기

새 공격을 처음 작성할 때는 이동·VFX 없이 판정부터 구성하면 입력값을 이해하기 쉽습니다.

`Combo Steps`를 3개로 만들고 아래처럼 입력합니다.

| 항목 | 1타 | 2타 | 3타 |
|---|---:|---:|---:|
| `Animation Name` | 빈칸 | 빈칸 | 빈칸 |
| `Duration` | 0.6 | 0.6 | 0.6 |
| `Damage` | 1.0 | 1.2 | 1.8 |
| `Hit Start Time` | 0.2 | 0.2 | 0.2 |
| `Hit Duration` | 0.1 | 0.1 | 0.1 |
| `Combo Transition Time` | 0.3 | 0.3 | 0.3 |
| `Poise Damage` | 20 | 20 | 20 |
| `Knockback Force` | 3 | 3 | 3 |

각 타수의 나머지 값:

```text
Hit Box Shape:          Box
Hit Box Offset:         (0, 1, 1.5)
Hit Box Size:           (0.6, 1, 2)
Hit Events:             0개
Thrust Multiplier:      0
Use Target Approach:    켜짐
Stop Distance:          0.25
Approach End Time:      0.2
Rotation End Time:      0.2
Max Approach Distance:  2
Slash VFX / Swing Sound: None
```

이 예시는 제자리 찌르기입니다. `Use Target Approach`가 켜져 있어도 이동 커브가 없으므로 자동 전진하지 않습니다. 같은 에셋의 `Skill Steps`, `Ultimate Steps`, `Counter Step`, `Air Attack Step`도 별도로 채워야 합니다. 기존 `IronFormAction.asset`을 복제해 일반 공격만 조정하면 나머지 설정을 유지할 수 있습니다.

## 8. 플레이어에게 연결하기

1. Hierarchy에서 플레이어를 선택합니다.
2. `Player Controller` 컴포넌트의 **CombatData** 영역을 엽니다.
3. 원하는 폼의 데이터 슬롯에 에셋을 드래그합니다.

| 코드 필드명 | 연결할 에셋 |
|---|---|
| `_FireFormActionData` | 화 공격 SO |
| `_WaterFormActionData` | 수 공격 SO |
| `_WoodFormActionData` | 목 공격 SO |
| `_IronFormActionData` | 금 공격 SO |
| `_EarthFormActionData` | 토 공격 SO |

인스펙터에서는 밑줄 없이 띄어쓰기된 이름으로 표시될 수 있습니다. `Weapon Name`에 `Fire`라고 적는 것만으로 화 폼에 자동 등록되지는 않습니다. 슬롯이 어떤 폼의 코드로 실행할지를 결정합니다.

프리팹으로 생성되는 플레이어라면 해당 플레이어 프리팹의 연결도 확인하세요. 기존 5개 외에 새로운 속성을 추가하는 것은 SO 생성만으로 완료되지 않으며, 새 폼 클래스와 `FormManagerSetup`의 등록·전환 입력 등이 필요합니다.

## 9. 자주 헷갈리는 문제

| 증상 | 확인할 항목 |
|---|---|
| 공격을 시작하면 인덱스/Null 오류 | 연결 슬롯, `Combo/Skill/Ultimate Steps`의 빈 목록·빈 항목 |
| 모션 없이 판정만 나옴 | `Animation Name`이 비어 있으면 정상. 모션 준비 후 State 연결 |
| 이름을 넣었는데 애니메이션이 안 나옴 | 트리거가 아니라 레이어 0 State 이름인지 확인 |
| 기본 타격 시간을 바꿨는데 변화 없음 | `Hit Events`가 채워져 있는지 확인 |
| 공격력이 너무 높음 | `Damage`가 고정 피해가 아니라 배율이라는 점 확인 |
| 공격 범위가 예상보다 두 배 큼 | `Hit Box Size`는 반쪽 크기 |
| 다단히트 일부가 사라짐 | 이벤트가 `Duration` 밖에 있거나 콤보 전환이 너무 빠른지 확인 |
| 적이 안 맞음 | 실제 Collider의 Enemy 레이어, 부모의 IDamageable, 오프셋·크기 확인 |
| 이동하지 않음 | 커브가 0인지, Multiplier가 0인지, 적 앞 정지 거리에 이미 도달했는지 확인 |
| 허공 공격에서 너무 멀리 전진 | `Max Approach Distance`가 아니라 커브와 Multiplier를 조정 |
| 이펙트가 타격보다 먼저 나옴 | 단계 시작 이펙트와 타격 이펙트의 차이 확인 |
| 물·토 궁극기의 타수/시간이 안 바뀜 | 전용 폼 코드의 고정값 확인 |
| 기즈모가 안 보임 | 현재 기즈모는 플레이 중 활성 타격 구간 위주로 표시. 반격·별도 장판 등의 전체 범위를 모두 보여주지는 않음 |
